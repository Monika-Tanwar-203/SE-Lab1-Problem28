# Static Code Analysis — Reflection

## 1. What did you learn from static code analysis?

I learned that static code analysis helps identify coding problems without executing the program. Pylint checks code quality and naming conventions, Flake8 identifies style violations, and Bandit detects potential security issues.

## 2. Which tool was most useful and why?

Pylint was useful for identifying code quality problems, such as naming conventions and missing docstrings. Flake8 helped improve formatting, while Bandit helped identify potential security risks.

## 3. What challenges did you face while fixing the issues?

I faced challenges understanding the warnings reported by the tools and deciding how to fix them without changing the program's behaviour. I resolved them by examining the relevant code and rerunning the tools.

## 4. How did you verify that your fixes worked?

I ran the blood donation management program to check that it still produced the expected output. I also reran Pylint, Flake8 and Bandit to review the remaining warnings and security findings.
